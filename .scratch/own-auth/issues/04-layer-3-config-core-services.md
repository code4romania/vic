  Choices worth checking:
  - `AuthException(code)` carries its own HTTP status (`AuthExceptionStatus`), because `ExceptionsService` only has 400/401/403/404/500 and this Nest version's `HttpStatus` has no 423 or 426. Body `{ message, code_error }` like every business exception; the existing filter passes it through.
  - Refresh rotation: `rotateSession(id, currentHash, newHash, expiresAt)` only updates while the row still holds the presented hash (Layer 2 repository changed), so two concurrent refreshes cannot both rotate. Inside the 10 s grace the answer is a new access token without a refresh token (the client keeps its own): only hashes are stored, so "return the current pair" is impossible. Rotation also requires the identity to be active and of the asking realm (AUTH_008 otherwise), which is what makes "disabled identity: refresh 401" hold.
  - `peekLink` / `findAnyByLink` without a type try the three type hashes (links are bound to the type only, R21); malformed secrets are refused before any query. `verifyCode` counts an attempt for a wrong or malformed code; the fifth ends the code (AUTH_006); a code with no live code row is AUTH_005.
  - Rate limits: fixed windows aligned to the clock (`auth:issue:<id>:<type>:minute:<bucket>` / `:hour:`, `auth:invite:<id>:10min:` / `:day:`); every call counts, refused ones too.
  - Emails: `mail-template.hbs` got optional `{{#if code}}` and `{{#if english}}` blocks now (planned for Layer 9), because otherwise the reset-code email has no code and there is nowhere for the English text. `{{#if}}` on a missing key is safe under strict mode (checked), so existing emails render unchanged; the spec renders one without them.
  - `AuthMailerService` builds `WEB_APP_URL/set-password?token=` and `/confirm-email?token=` and queues through `MailService`.
