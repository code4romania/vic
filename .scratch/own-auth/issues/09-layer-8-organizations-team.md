# Layer 8 · NGO registration, validation gates, super admin, Team

Status: done (built and tested locally, 2026-11-03)
Type: task
Blocked by: 08

Everything NGO Hub did for organizations and admins, plus the validation a VIC super admin performs after sign-up (design doc decisions 1, 2, 4). The organization, Team and super admin routes are fixed at this layer; web issues 13 and 14 are blocked by it (decisions R25).

## Comments
- 2026-11-02: Layer 8 built locally (uncommitted). Decided with Laurentiu today:
  - **Logos (deviation from decisions R27, needs Dragos):** new logos go to the existing **public** bucket (the one in `AWS_S3_BUCKET_NAME_PUBLIC`, which the emails already use for images) and the full URL is stored, so new and legacy NGO Hub logo URLs look alike and none of the 8 presenters that print `logo` change. R27's "presign in the transformer" cannot work: presigning is async and those presenters are synchronous. Statutes stay private keys in the default bucket, presigned (one day) only where shown: the NGO's own `GET /organization`, the super admin review page and the "new NGO" email.
  - **Local S3:** the local `backend/.env` pointed at the staging bucket `vic-staging-private-enid`; it now points at a local S3 emulator (docker `vic-own-auth-s3`, `adobe/s3mock:3.12.0` on :9090, buckets `vic-local-private` and `vic-local-public`), with the staging lines kept commented. MinIO's images are no longer pullable from Docker Hub or Quay. New optional settings, unset in staging and production: `AWS_S3_ENDPOINT` (S3Service uses it with path-style addressing), `AWS_S3_PUBLIC_BUCKET`, `AWS_S3_PUBLIC_BASE_URL`; otherwise the public bucket is derived from the `AWS_S3_BUCKET_NAME_PUBLIC` host.
  Other choices worth checking:
  - Gates (ORG_005, `OrganizationGateService`): event creation, hours by admin and by volunteer, approving hours, joining by access code, and **also creating an access request** (not in the plan, but otherwise a hidden NGO could still be asked to join). The app's list and organization profile hide NGOs that are not active and validated.
  - Team: an admin with no VIC login yet shows as `no_login` (a fifth status beside the four planned). Send invite creates their login; Disable creates it disabled, so the cutover import (which never overwrites) keeps them out. New codes ORG_008 (not in your organization, 403), ORG_009 (invite only for admins without a password, 400), ORG_010 (not your own status, 400). Logo type errors reuse ORG_003.
  - Registration answers 409 ORG_004 also when the admin email already has a web login or an admin profile. `acceptedTerms` reads the raw form value: the global pipe's implicit conversion turned "false" into true (caught by the e2e spec).
  - `OrganizationRepositoryService.update` is generic and takes a manager; `UpdateOrganizationDescriptionUseCaseService` and its DTO are replaced by `UpdateOrganizationUseCase` / `UpdateOrganizationDto` (every field, multipart, uniqueness against the others). `GET /organization` now returns `OrganizationPresenter` (with the statute link) instead of the raw model.
  - Turnstile is faked in the e2e harness (`TURNSTILE_OK`); e2e `testTimeout` is 20 s (one full run had 3 failures under CPU load during a build and a dev-server restart; not reproduced in 9 further runs, most likely the 5 s default timeout).
  Checked: build, lint, `npm run test` (201 tests), `npm run test:e2e` (46 tests, incl. `organization-registration` 7 and `team` 7), Swagger lists the 12 routes. Removing the event gate or the hiding filter makes 4 registration specs fail.
