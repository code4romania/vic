## Comments
- 2026-10-30: Layer 4 built locally (uncommitted). From here the local API refuses Cognito tokens, and nothing issues VIC tokens over HTTP until Layer 7, so the current web and mobile apps cannot log in against this backend.
  **Deviation from decisions R2, needs Dragos:** the maintenance allow-list uses `req.ip` with `trust proxy` 1, not "the first `X-Forwarded-For` hop". The ALB appends the address it saw to whatever `X-Forwarded-For` the client sent, so the first hop is client-controlled: anyone sending `X-Forwarded-For: <office IP>` would pass maintenance while the database is being migrated. The last hop (the one the ALB added) is what `req.ip` returns with one trusted proxy. `test/guards.e2e-spec.ts` covers both: the allow-listed address as the ALB's hop passes, the same address written by the client in front of another hop gets 503. If a CDN is ever put in front of the ALB, `trust proxy` must count it.
  Other choices:
  - Strategies: RS256 public key, `iss vic-api`, `aud vic-web` / `vic-mobile`; the identity must exist, be `active` and belong to the strategy's realm, else 401. Web: null `userId` or no admin row → 401; suspended organization → 403 AUTH_004 (via `OrganizationFacadeService`; `AuthenticationModule` now imports `OrganizationModule`, which depends on nothing in auth or user). Mobile: null `userId` → `{ identityId, sessionId, email, role }` without querying users; a `userId` whose row is gone → 401. Types in `interfaces/request-user.interface.ts`.
  - `src/app.setup.ts` (`setupApp`): trust proxy, cookie-parser, CORS limited to `CORS_ORIGINS` with credentials, the exception filter and the validation pipe; used by `main.ts` and the e2e harness so tests run the same app. Helmet stays in `main.ts`.
  - `app.module.ts`: `configure` (was `onfigure`) applies only `MaintenanceMiddleware` to `*`; the RawBody / JsonBody registrations are dropped, their files kept (say so in the PR). `MobileVersionGuard` is a global `APP_GUARD`, uses `semver.coerce` so `1.1` and `1.1.0` compare alike.
  - `src/api/auth/cookies.ts`: `setRefreshCookie(res, secret, authConfig)` and `clearRefreshCookie(res)` (the config is needed for `maxAge`).
  - `jwt-all.guard.ts` deleted (unused). `SuperAdminGuard` provided and exported.
  - Known gap until Layer 7 (unchanged from today's Cognito stub): mobile routes that use `user.id` with a profile-less volunteer still call the facade with `undefined`. Layer 7 adds the USER_001 guard.
